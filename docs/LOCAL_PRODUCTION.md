# LOCAL_PRODUCTION.md — Windows 本地生产运行约束

> 定位声明：work-cloud 是**个人真实场景本地自动化执行器**。
> 不云化、不接平台、不做数据库。本文件是它在 Windows 上的生产运行约束与操作手册。

---

## 1. 运行形态

```
Windows 任务计划程序（Task Scheduler）
        │
        ▼
python scheduled_runner.py      ← 常驻调度器（推荐）
        │  每日窗口内随机触发 2 次
        ▼
main.py（execute_tasks）        ← 单实例锁 + 只读预检 + 执行 + 台账
```

两种部署方式二选一：

| 方式 | 命令 | 适用 |
|---|---|---|
| **常驻调度器**（推荐） | `python scheduled_runner.py` | 开机自启一次，进程内按窗口触发 |
| 计划任务直触 | 每日 2 个计划任务分别执行 `python main.py` | 不想留常驻进程 |

## 2. Task Scheduler 配置要点

1. **操作**：`程序: <python.exe 绝对路径>`，参数留空（调度器）或空（main.py 直触时无参数）；
   **起始于** 必须填仓库根目录（模型路径已改为绝对路径，此项仅为保险）。
2. **触发器**：调度器方式 → 「登录时」+「启动时」各一条；
   直触方式 → 每日 09:00 与 18:30 各一条（实际触发窗口见第 4 节）。
3. **设置**：勾选「如果任务失败，每 1 分钟重试，最多 3 次」；
   不要勾选「错过计划开始后立即启动任务」超过 1 次的选项，避免积压连跑。
4. **电源**：勾选「唤醒计算机运行此任务」（如机器会睡眠）。

## 3. 单实例要求（L1）

- 同一时刻**只允许一个 work-cloud 进程**：第二个进程会在
  `execute_tasks` 入口被 `data/run.lock` 内核锁直接拒绝并退出，
  同时记录 `SECOND_INSTANCE_BLOCKED` 风险事件。
- 内核锁随进程死亡自动释放：崩溃/断电后**无需手工清理锁文件**。
- 手动运行前若提示"另一个进程正在运行"，先用任务管理器确认常驻调度器是否在跑，**不要强删 `data/run.lock`**。

## 4. 上午/下午任务

- 默认触发窗口：**09:00–09:10**、**18:30–18:40**，每次在窗口内随机取时刻（避免固定分钟）。
- 可用环境变量覆盖（不改配置文件格式）：
  ```bat
  set WORKCLOUD_SCHEDULE={"windows": [["08:00","09:30"],["18:00","23:00"]]}
  ```
  非法 JSON / 非法窗口自动回退默认窗口。
- 每次触发 = 该用户全部已启用任务的一轮完整尝试（打卡 → 日报 → 周报 → 月报），
  已成功任务由幂等层跳过。

## 5. 周报/月报任务

- 周报：按 `config.reportSettings.weekly.submitTime`（周几）在当周首次触发的轮次提交；
- 月报：按 `config.reportSettings.monthly.submitTime`（几号）在当月首次触发的轮次提交；
- 提交前后均有服务端去重 + 本地幂等 + L3 只读核验，重复周期内不会重复提交；
- 生成内容经 Stage 6 校验（长度/占位符/历史相似度），重复会重生成一次。

## 6. 手动运行方式

```bat
cd /d <仓库根目录>
python main.py                     :: 全部用户配置跑一轮
python main.py --file example      :: 只跑指定配置
python -m models.statistics        :: 汇总执行统计 -> data/statistics.json
python -c "from models.risk_ledger import daily_summary; print(daily_summary())"
```

手动跑与计划任务跑走完全相同的单实例锁/预检/幂等路径，随时可安全执行。

## 7. 日志与台账位置

| 内容 | 位置 | 说明 |
|---|---|---|
| 结构化日志（JSON Lines） | `logs/YYYY/MM/DD/app.log` | 含完整异常堆栈 |
| 当日任务状态 | `data/{日期}_{用户}.json` | 幂等判断依据 |
| 每日执行台账 | `data/history/{日期}.json` | 每用户开始时间/耗时/各任务结果 |
| 风险事件台账 | `data/risk/{日期}.json` | L6 事件（用户已脱敏） |
| 执行统计汇总 | `data/statistics.json` | `python -m models.statistics` 生成 |
| 图片上传记录 | `data/uploads/{日期}_{用户}.json` | 成功 key / 失败原因 |

> `data/`、`logs/` 均不入库（.gitignore）。删除它们是安全的：
> 最多丢当日幂等记忆与本地历史，服务端去重会兜底防止重复提交。

## 8. 异常处理

程序内置的保护层级（按触发顺序）：

1. **单实例锁**（L1）：并发进程直接退出；
2. **只读预检**（L5）：配置缺失/时钟异常/网络不可达/任务已全部完成 → 不发任何业务请求；
3. **登录分类**（Stage 3）：密码/验证码/超时/网络/服务端 6 类，分类结果直达通知；
4. **UNKNOWN 收敛**（L2+L3）：提交后无响应/5xx → 只读核验 → 最多一次补偿 → 仍未知则停止；
5. **验证码熔断**（L4）：验证码处理超限立即停止当前任务并**阻断该用户剩余任务**（ERROR 通知）；
6. **有限重试**（Stage 4）：仅查询类重试（≤3 次指数退避），提交类永不盲目重试 POST。

收到 `[ERROR]` 通知时按通知中的分类信息处理；详细信息查当天的 `app.log` 与 `data/risk/`。

## 9. 回退方法

- **代码回退**：`git log --oneline` 找到上一个正常版本，`git checkout <commit> .` 后重跑即可；
  所有 L 系列 commit 均独立、可单独回退。
- **禁用某用户**：把该用户 JSON 移出 `user/`（配置白名单机制只加载 `user/*.json`）。
- **关闭报告功能**：`config.reportSettings.{daily,weekly,monthly}.enabled` 置 `false`。
- **回退运行数据**：删除对应日期的 `data/` 与 `logs/` 文件即可，不影响代码。

## 10. 运行环境约束（重要）

程序按"固定环境 + 固定账号 + 固定设备参数"设计，**不承担任何"模拟真人"职责**：
不含随机 User-Agent、不含 IP/代理轮换、不含虚假定位、不含验证码高频自动尝试。

因此，**任务执行窗口（09:00–09:10、18:30–18:40 及环境变量自定义窗口）内请不要主动切换**：

- 网络（Wi-Fi ↔ 有线 ↔ 热点）；
- VPN / 代理出口；
- 系统代理设置；
- 设备参数与账号环境。

执行中途切换出口是造成超时/UNKNOWN 的最大人为来源——程序的 L2/L3 层会保证这类中断**不产生重复提交或假成功**，但避免它仍是第一优先级。

## 11. 与 14 天验证（L8）的衔接

L8 观察期每日检查项与数据源：

| 检查项 | 数据源 |
|---|---|
| 上午/下午签到执行与结果 | `data/history/` + 通知 |
| 周报/月报按周期执行 | `data/history/` |
| 验证码出现与熔断 | `data/risk/`（CAPTCHA_*） |
| UNKNOWN 出现与收敛 | `data/risk/`（SUBMIT_UNKNOWN） |
| 重复执行/重复提交 | 单实例锁日志 + DUPLICATE_PREVENTED 计数 |
| 台账与平台一致 | `data/history/` vs 平台人工抽查 |
| 通知准确性 | 推送消息 vs `data/history/` |

通过标准见 `docs/VALIDATION_PLAN.md`；观察期内除阻断性缺陷外不改功能。
