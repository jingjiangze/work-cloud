## 2. 每日检查清单（约 5 分钟）

1. 上午窗口（09:00–09:10）签到：通知是否收到、状态是否成功；
2. 下午窗口（18:30–18:40）签到：同上；
3. 周报（周日）/月报（月末）是否按周期提交；
4. 是否出现验证码（`data/risk/` 中 CAPTCHA_REQUIRED）；
5. 是否出现 UNKNOWN（SUBMIT_UNKNOWN）及其最终收敛结果；
6. 是否发生重复执行（同用户同日多轮成功记录）；
7. 是否发生重复提交（平台侧记录 vs 本地台账）；
8. 本地台账（`data/history/`）与平台实际状态是否一致；
9. 通知是否准确（分级前缀、内容与实际相符）；
10. 是否有异常请求循环（app.log 中同一接口短时高频重复）。

## 4. 异常时的处置规则

| 情况 | 处置 |
|---|---|
| 阻断性缺陷（漏打卡/假成功/死循环） | 停表 → 最小范围修复 → 独立 commit → **观察期重新计 14 天** |
| 误报类缺陷（如重复检测误判） | 调参修复 + 独立 commit，观察期**延长 3 天** |
| 平台侧临时故障 | 记录当日，不计入程序缺陷 |
| UNKNOWN 事件 | 不干预，先看是否被 L3 自动收敛，收敛即视为通过 |
